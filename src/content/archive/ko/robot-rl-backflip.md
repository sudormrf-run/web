## RL 이론 vs 응용

RL을 배울 때 이론과 실제 응용 사이의 차이가 크게 느껴질 수 있다. 이 격차를 이해하는 것이 중요하다.

핵심 개념:

- [02:12] RL은 단순히 보상을 "수집"하는 것 이상의 문제 - **탐색(exploration)과 활용(exploitation) 사이의 균형**이 핵심
- [04:09] RL 학습 중 **모드 붕괴(mode collapse)** 현상 발생 가능 - 탐색이 부족하면 에이전트가 단일 행동으로 수렴
- [04:35] 해결책: 탐험 계수를 높여 충분한 탐색을 유도한 후 활용으로 전환
- [05:42] PPO에는 학습 안정성에 큰 영향을 주는 핵심 항(term)이 소수만 존재

PPO가 로봇 이동에서 선호되는 이유:

- [06:43] PPO는 **온라인(on-policy)** 정책 학습으로, 학습이 "분포 내(in-distribution)"에 머무르도록 장려
- [07:10] 오프라인 RL은 더 효율적이지만 **분포 이동(distribution shift)** 문제 발생 가능
- [08:03] 로봇 이동 연구자의 **90%**가 PPO를 사용

> "[02:12] RL은 단순히 보상을 수집하는 것 이상이라고 생각합니다."

## Sim-to-Real 격차 해결

시뮬레이션과 현실 사이의 격차를 줄이는 것은 로봇 배포의 핵심 과제다.

권장 파이프라인:

- [08:56] 1단계: 로봇의 시스템 식별(system identification)을 정확하게 수행
- [09:03] 2단계: 시뮬레이션에서 명목값 주변으로 **도메인 랜덤화** 적용
- [09:09] 3단계: 로봇에 정책 배포 후 불일치 확인
- [09:31] 4단계: 실제 배포 후 수집한 데이터로 시뮬레이션 파라미터 수정 (루프 반복)

현실 세계 RL의 어려움:

- [09:55] 실세계 RL은 시간이 매우 오래 걸림
- [10:03] 하드웨어 손상 위험이 있고, 하드웨어가 비쌈
- [10:46] 컨트롤러를 켜자마자 로봇이 난폭하게 움직이는 경우 발생

하드웨어 문제의 원인:

- [10:59] IMU 캘리브레이션 부정확 → 위치/각속도/선속도 감각 부정확
- [11:16] 모터가 필요한 토크를 내지 못함 (특히 민첩한 동작에서)
- [12:12] 제조사 기본 파라미터만으로는 정확하지 않음
- [12:47] 모터 특성은 시간이 지나며 변화 → 시뮬레이션 모델링 어려움

> "[09:20] 로봇의 계수들을 식별하고 시뮬레이션에서 랜덤화한 뒤, 실제에 배포하고 역전파로 파라미터를 다시 시뮬레이션으로 되돌립니다."

## 커스텀 로봇에 RL 배포하기

커스텀 로봇에 RL을 배포할 때 필요한 핵심 요소들이다.

시스템 식별 필수 사항:

- [14:22] **시스템 식별(SYS-ID)**을 매우 신중하게 수행
- [14:29] 로봇 전체의 관성(inertia)과 질량 측정 (모터 포함)
- [14:36] IMU, 엔코더, 깊이 카메라 등 센서 캘리브레이션
- [15:46] 가장 중요한 요소: **모터 전기자(armature)의 회전 관성**

컨트롤러 구조:

- [14:44] 매우 견고한 로우레벨 컨트롤러 필요
- [17:30] 실행 주파수: 상위 RL 정책 **50Hz**, 하위 토크 명령 **500Hz**
- [21:52] 상위 RL 정책 출력은 PD 위치 타깃을 설정하는 형태
- [24:46] 모든 모터에 **매우 작은 PD 게인** 사용 → Sim-to-Real 격차 감소

주파수 트레이드오프:

- [19:21] 높은 주파수: 빠른 환경 반응이지만 GPU 메모리/전력 소모 증가, 지연 문제
- [19:56] 낮은 주파수: 환경 변화에 충분히 빠르게 반응 못함
- [20:30] 낮은 주파수가 더 안정적 - "부드러운 매니폴드"에서 탐색

> "[24:50] 매우 작은 PD 게인을 사용합니다."

## RL 시뮬레이터 비교 (Isaac Lab vs MuJoCo)

시뮬레이터 선택은 학습 효율과 시뮬레이션 정확도 사이의 트레이드오프다.

Isaac Lab의 장점:

- [26:47] 높은 병렬화 가능, 분산 학습 지원
- [26:56] 렌더링 품질이 매우 좋음
- [27:00] 비전 기반 RL로의 확장 지원

MuJoCo의 역할:

- [27:22] 더 높은 **충실도(fidelity)**의 시뮬레이션 모델
- [27:41] **Sim-to-Sim 검증**에 사용 - Isaac에서 학습 후 MuJoCo에서 테스트
- [28:22] 더 정확한 **접촉(contact) 모델링**

시뮬레이터 스펙트럼:

- [28:42] Isaac: 처리량(throughput) 높은 쪽
- [28:50] MuJoCo: 중간 (충실도와 속도 균형)
- [29:04] Drake: 가장 정확하지만 GPU 미지원, 병렬화 어려움

Sim-to-Sim 검증의 가치:

- [30:18] 비전 지연 같은 문제 디버깅에 유용
- [32:38] 배포 코드를 시뮬레이션에서 먼저 테스트 가능
- [33:01] MuJoCo는 추론 코드 배포에 더 직접적인 인터페이스 제공

> "[27:41] 저희가 MuJoCo를 Sim-to-Sim 검증으로 사용하고 있습니다."

## 키네마틱 리타게팅

인간의 동작을 로봇에 전이하는 기술로, 휴머노이드 로봇에서 특히 중요하다.

기본 개념:

- [35:56] **키네마틱 리타게팅**: 인간의 동작을 로봇의 동작으로 옮기는 것
- [36:23] 사람과 로봇에 **핵심 포인트(key points)**를 정의해 매칭
- [36:36] 문제: 휴머노이드가 사람보다 작으면 직접 매칭 시 **물체 관통** 발생

인터랙션 메시 접근법:

- [40:33] **인터랙션 메시** 구축 - 사람과 물체 사이의 상대 위치 포착
- [41:17] 사람과 물체의 관계를 그래프 구조로 포착해 전이 시 보존
- [41:47] 사람의 오른손이 물체의 오른쪽 면을 만지면, 로봇도 동일하게
- [42:46] 물체에서 **20~50개의 포인트**를 샘플링해 관계 유지

데이터 소스:

- [38:38] 현재는 모션캡처(mocap) 데이터 사용
- [39:02] 장기 목표: 인터넷 비디오 활용
- [39:11] 비디오에서 3D 재구성은 아직 어려운 연구 문제

> "[35:56] 키네마틱 리타게팅은 기본적으로 인간의 동작을 로봇의 동작으로 옮기는 것입니다."

## 범용 정책 vs 특화 모델

로보틱스에서 범용 모델과 특화 모델 사이의 논쟁이 활발하다.

범용 정책의 장점:

- [44:58] 여러 기술이 서로 전이되어 일반화 가능
- [45:16] **상식/직관(직관적 물리)** 같은 대략적 모델 학습 가능
- [45:35] 새로운 과제에도 더 쉽게 전이
- [47:23] 실패로부터 학습해 복구 시도 가능

정밀 작업에 대한 견해:

- [46:25] 범용 정책이 처음부터 밀리미터 정밀 작업 수행은 어려움
- [46:40] 소수의 시연 데이터로 **파인튜닝**하면 높은 정확도 달성 가능
- [47:06] 전통적 방법은 **롱테일(long-tail) 문제**에 취약

> "[44:58] 저는 개인적으로 범용 정책입니다."

## 데이터와 학습 전략

가정용 로봇 개발의 가장 큰 걸림돌은 데이터 문제다.

현재 상황:

- [48:12] 휴머노이드 하드웨어는 상대적으로 견고
- [48:29] **소프트웨어 문제의 핵심은 데이터 문제**
- [48:37] 충분히 높은 품질의 데이터가 있으면 아키텍처 중요도 감소

데이터 출처별 특성:

- [50:06] **텔레오퍼레이션**: 가장 비싸지만 가장 높은 품질
- [50:13] **시뮬레이션**: 대규모 생성 가능하지만 Sim-to-Real 격차 존재
- [50:28] **인터넷 비디오**: 풍부한 의미 정보와 시각적 특징, 하지만 행동 데이터 부족

권장 데이터 비중:

- [51:47] **시뮬레이션 데이터: 약 50%** - 확장 가능하고 정확한 동역학/행동 데이터 제공
- [51:53] 나머지 50%는 비디오 데이터와 텔레오퍼레이션으로 분배
- [52:44] 확장 가능한 방법(시뮬레이션, 비디오)에 최대한 투자하되, 실제 데이터로 Sim-to-Real 격차 감소

> "[48:29] 많은 연구자들에게 소프트웨어 문제의 핵심은 데이터 문제입니다."

## 전통적 최적화와 RL의 결합

최적화 기반 방법과 학습 기반 방법을 결합하는 것이 유망한 방향이다.

최적화 기반 방법의 장점:

- [54:10] **하드 제약**을 직접 다룰 수 있어 더 높은 품질 보장
- [54:25] 물체 관통, 관절 한계 초과, 속도 임계값 초과 등을 하드 제약으로 방지
- [55:10] 제약을 "체계적이고 엄격하게" 강제 가능

학습 기반 방법의 한계:

- [54:40] 제약을 **소프트 페널티**로 비용/보상에 넣어 최적화
- [54:55] 하드 제약이 실제로 강제된다는 보장 없음

계층적 프레임워크:

- [55:36] 두 가지 **결합**이 목표
- [55:44] 상류: 최적화 기반 하드 제약으로 **고품질 데이터 생성**
- [55:52] 하류: 그 데이터를 추종하도록 **RL 정책 학습**
- [01:01:48] RL 학습 시 에이전트를 동작 데이터셋의 임의 시간 스텝에서 초기화
- [01:02:09] 그 상태에서 RL이 부트스트랩하여 동역학적으로 실현 가능한 해 탐색

> "[55:36] 두 가지의 결합이 사실 제 목표입니다."
> "[01:01:41] 이것은 사실 일종의 계층적 프레임워크입니다."
